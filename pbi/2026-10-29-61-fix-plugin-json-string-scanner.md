# PBI: plugin プロトコルの JSON 抽出を文字列状態を追うスキャナに置き換える

## ユーザーストーリー
プラグインを書くユーザーとして、`{"freed": n}` の JSON 文字列値に `}` が含まれていても（ファイル名などに合法的に現れる）、プラグインの申告が正しく parse されたい。なぜなら、現在は波括弧カウントで文字列状態を追っておらず、文字列値内の `}` でオブジェクトが途中切断され、そのプラグインは以後恒久 unavailable（scan）と 0 freed（clean）になるから。

## 優先度
- 順位: 61 / 全 9 候補
- RICE スコア: 12.0（Reach=1 / Impact=3 / Confidence=100% / Effort=0.25 人週）
- 根拠: `extract_last_json_object`（src/cleaners/plugin.rs:65-91）は `{`/`}` の深さカウントのみで、JSON 文字列リテラル内の `}` を区別しない。serde_json が parse 失敗し、プラグインは恒久 unavailable になる（fail-closed で誤ったデータは取らないが、正当なメッセージが永遠に parse されない）。doctest（plugin.rs:58-63）が切断を文書化している

## ビジネス価値
- 文字列値に `}` を含む合法的な JSON を出すプラグインが恒久 unavailable になるバグのクラスが消える
- プラグインプロトコルの信頼性が上がり、サードプラグインが書きやすくなる
