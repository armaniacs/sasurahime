# PBI: ポリシーエンジンと定期実行の仕組み

## ユーザーストーリー
macOS開発者として、`keep 2 versions / older than 30d` と書けば放置で綺麗になってほしい、なぜなら毎回 `scan` して選ぶ運用は続かず、気づいたときには数十GBに戻っているから

## ビジネス価値
運用の自動化で再肥大化を防ぐ。cronよりOS標準の定期実行に乗ることで、CI外の日常利用に効く。

## 優先度
- 順位: 03 / 4（新規分のみ）
- RICEスコア: 90（Reach=300 / Impact=3 / Confidence=50% / Effort=5.0人週）
- 根拠: 将来価値は大きいが、キャッシュ（01）・フィルタ統一（02）が前提で、macOS定期実行のハードルもあり後回し。依存はスコアより優先。

## BDD受け入れシナリオ
Scenario: ポリシーを書けば自動で刈り取られる
  Given `keep 2 versions` と書いた config がある
  When 定期実行が走る
  Then ポリシー外だけ削除され、結果が履歴に残る

Scenario: 危険な操作は自動では走らない
  Given 不可逆ターゲットを含むポリシーがある
  When 定期実行が走る
  Then 不可逆操作はスキップされ、明示実行の導線が示される
